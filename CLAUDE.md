# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Purpose

Research project on the **magnitude** (scale, not mean bias) of U.S. CES payroll revisions across four stages — first → second print, second → third, third → annual benchmark, and post-benchmark wedge-back — plus a Bayesian state-space design in which collection-interval, seasonal-adjustment, sample, BLS-funding, and staffing covariates enter the revision *variance*. The Python package holds the marginalized Kalman engine (`src/ces_revisions/kalman.py`), the Stage 3 vintage panel (`src/ces_revisions/vintages/`), the Stage 4 annual-source tables (`src/ces_revisions/annual/`), the sparse deterministic operator layer (`src/ces_revisions/operators/`), the Stage 6 aggregate pilot (`src/ces_revisions/pilot/`), the Stage 1 scale model (`src/ces_revisions/scale_model/`), and the model-agnostic run harness (`src/ces_revisions/runs/`). Work is staged by the outcome-first roadmap `specs/ces-revision-drivers-roadmap.md`, whose reset is recorded in `specs/findings/ces-revision-drivers-reset-review.md`. The original design spec `specs/completed/ces-revisions.md` and its roadmap `specs/completed/ces-revisions-roadmap.md` are parked as background, and a stage number elsewhere in this file means a stage of that parked roadmap. Decision records live in `docs/decisions/`, and the Req 20 written finding in `docs/ces-revisions-review.md`, with its evidence in `docs/inventory/`.

## Specs

- `specs/completed/ces-revisions-prompt.md` — the research brief: required sections, the five candidate drivers, and the design requirements. Treat it as the statement of scope.
- `specs/completed/ces-revisions-research-{chatgpt,claude,gemini}.md` — three independent AI-generated responses to that brief. They are unverified drafts: figures, dates, and citations have not been checked against primary BLS sources, and the documents disagree with each other (e.g. the gemini draft puts the post-pandemic first-closing rate near 40%, while the chatgpt and claude drafts give 60.4% for 2024 — collection and response rates are easy to conflate). Verify a claim against primary sources before building on it. Drafts are replaced wholesale when regenerated; re-normalize a replacement to the conventions below before committing it.

Markdown in `specs/` is kept GitHub-renderable. Freshly pasted AI output usually arrives with `$…$`/`$$…$$` or `\(…\)`/`\[…\]` math and needs converting. When adding or editing:

- Put display math in ```` ```math ```` fences and inline math in `` $`…`$ ``. Do not use `\(…\)`, `\[…\]`, `$$…$$`, or bare `$…$`: GitHub ignores the backslash forms, and Markdown escapes/emphasis can corrupt TeX inside bare dollars (`\%` loses its backslash; a lone `=` or `-` line in unfenced math becomes a setext heading).
- Escape literal dollar amounts as `\$` (e.g. `\$544.3 million`, `(\$m)`); an unescaped pair on one line is read as math, and a `|` inside it splits table cells.
- Use real headings (`##`, `###`), not bold-only lines, and write hard line breaks as a trailing `\` rather than two trailing spaces, which whitespace cleanup silently deletes.
- Put non-TeX pseudo-math containing `_` (e.g. `θ_{s,t}`) in code spans so underscores are not read as emphasis.

## Layout and tooling

- `src/ces_revisions/` is an installable package (src layout, `uv_build` backend). `main()` in `__init__.py` is exposed as the `ces-revisions` console script via `[project.scripts]`. `uv_build` expects the module at `src/ces_revisions`, matching `name = "ces-revisions"` in `pyproject.toml`; rename both together.
- Python 3.14 (`.python-version`; `requires-python = ">=3.14"`) and uv 0.13: `[tool.uv] required-version = "~=0.13.1"` holds the Mac and any GPU host to one uv series, so `uv.lock` is written one way. Runtime dependencies are JAX, NumPy, NumPyro, ArviZ 1.x (`az.from_numpyro` returns an xarray `DataTree`), Polars, fastexcel (Polars' Excel reader, for Stage 3's workbooks), python-dotenv (the Stage 4 network-command contact configuration), SciPy (ranks for the Req 18 diagnostics and the Ljung–Box p-value), and h5netcdf with h5py (the netCDF backend that writes each run's `DataTree` to one file). The `cuda` extra adds `jax[cuda13]` on Linux only: on an NVIDIA host `uv sync --extra cuda` installs JAX's CUDA 13 plugin, and on the Mac it installs nothing. Dynamax is a dev-only dependency kept as evidence for `docs/decisions/engine.md`, and matplotlib is a dev-only dependency that draws the scale model's report figures through ArviZ.
- `src/ces_revisions/kalman.py` is the hand-written, NaN-masked Kalman filter and smoother chosen in `docs/decisions/engine.md`. Models add its log likelihood with `kalman_factor`, so states are never sampled sites. All JAX work is float64: `numpyro.enable_x64()` (and `numpyro.set_host_device_count`) must run before the first JAX operation, which `tests/conftest.py` does for the test session, adding XLA's deterministic GPU flag on hosts with `/dev/nvidia0`. BlackJAX waits for the sampler benchmark (roadmap Stage 17); confirm Python 3.14 support for any package you add.
- `src/ces_revisions/devices.py` holds the host's device facts: `has_nvidia_device()`, the `DETERMINISTIC_GPU_FLAG` that `tests/conftest.py` adds to `XLA_FLAGS`, `jax_versions()` and `nvidia_driver()`, which run and grid records copy, and `chain_method(num_chains)`, which returns NumPyro's `"parallel"` when JAX sees a device per chain and `"vectorized"` otherwise. A CPU host has the four host devices that `tests/conftest.py` sets, and a GPU host has one device per GPU, so pass `chain_method(n)` to `MCMC` instead of writing `"parallel"`, and never assume a GPU count.
- `src/ces_revisions/engine_probe.py` times the engine's value and gradient on the current host (`python -m ces_revisions.engine_probe`) and writes one JSON record. Records are committed to `docs/decisions/cloud-gpu-probe/`, which holds the Mac baseline beside the Stage 6 grid records from `scripts/gpu_probe_grid.py`.
- GPU work runs on an NVIDIA instance rented by hand from Lambda (lambda.ai): install uv from the pinned 0.13 series (`required-version` refuses any other), clone the repo, check that `nvidia-smi` reports driver 580 or later (the minimum for JAX's CUDA 13 wheels), then `uv sync --extra cuda`. Lambda bills by the minute until the instance is terminated in its console or API; an OS shutdown does not stop billing, and termination deletes the instance's disk, so copy results off first. The repo holds no cloud infrastructure or account configuration. The GPU type and count follow what the model requires, measured with the engine probe by plan 11's Task 13, which `specs/ces-revision-drivers-roadmap.md` places under outcome O6; A10 and A100 instances are usually available, and float64 makes them far apart (see Stage 6 in `specs/completed/ces-revisions-roadmap.md`).
- `src/ces_revisions/operators/` owns only deterministic preprocessing and sparse float64 JAX maps. Axis order is fixed in `operators/__init__.py`; benchmark years use December-to-January adjacent vintages; the selected public post-March representation is recorded in `docs/decisions/link-relatives.md`. Rebuild its gitignored parquet and `operator-test-results.json` with `uv run python scripts/operator_artifacts.py build`; every later run copies that record into provenance.
- `src/ces_revisions/pilot/` implements roadmap Stage 6: the aggregate total-nonfarm panel (`assembly.py`, `panel.py`), the three seasonal layouts (`layout.py`), the marginalized Jacobs–van Norden pilot (`model.py`), its simulator and prior predictive (`simulate.py`), SBC (`sbc.py`), the April 2020 check (`checks.py`), the Stage 7–9 dimensions (`dimensions.py`), the pre-registered seasonal rule (`seasonal.py`), recorded in `docs/decisions/seasonal-state.md`, and the GPU rule (`gpu_choice.py`), which waits for O6. NUTS runs at `TARGET_ACCEPT_PROB = 0.95` from `model.py`: at 0.8 the pilot diverges.
- `src/ces_revisions/runs/` is the model-agnostic run harness every fit uses: dispersed chain starts (`inits.py`), NUTS and the run directory (`fit.py`), Req 18 diagnostics (`diagnostics.py`), the log likelihood grouped by reference month and benchmark year (`inference_data.py`), and provenance (`provenance.py`). Run directories go to the gitignored `data/runs/`; small JSON evidence is committed under `docs/runs/`.
- `src/ces_revisions/scale_model/` is the Stage 1 scale model of `specs/stage-1-scale-model/recommendation.md` (Fit 1): a location-scale Student-t regression on the signed revision (`signed_revisions` in `ces_revisions.collection_window`), 2003+ only, one series at a time, through the run harness. `data.py` builds the design arrays (the window centered within year over non-lapse months, and 0 at the four lapse months), `model.py` the model and priors, `checks.py` the predictive statistics and the prior-predictive and sensitivity rules, `fit.py` the completed DataTree (pointwise log likelihood `r`, posterior predictive, log prior for psense), and `sbc.py` its calibration with a pre-registered pass rule. `scripts/scale_model_run.py` drives it (`prior-predictive`, `fit`, `sensitivity`, `sbc`, `sbc-summary`), writing runs to `data/runs/` and evidence to `docs/runs/stage-1-scale-model/`, whose `report.md` follows the bayesian-workflow skill's template. No test guards that evidence: after a refit, check the report's figures by hand. The report lists the model's four deviations from the recommendation, and `specs/deferred_items.md` holds the deferred A′, Fit 2 and Gamma cross-check.
- Roadmap Stage 9 (`specs/completed/ces-revision-drivers-stage-9.md`) asks whether the window to first closing `W_t` or the first-closing collection rate C1 explains revision size. `W_t` (`ces_revisions.vintages.collection_days`) follows the owner's rule: "first closing, when BLS stops collecting survey responses for the first estimate, falls one week before the release" (owner, 2026-11-17). `src/ces_revisions/vintages/collection_rates.py` parses C1, C2 and C3 from the LABSTAT extract and from the table of each archived registry page (rows of innermost tables only, because the 2008–2019 pages nest the table in a layout table), and compares each archived value with LABSTAT's as integer tenths (spec D8). `scripts/first_closing.py check` (offline) prints that comparison from the built `data/panel/collection_rates.parquet` and exits 1 on any difference not in `ACCEPTED_DIFFERENCES`. Its one entry, C1 for June 2012 in the 2012-11-14 copy (64.6 against LABSTAT's 72.9), the owner accepted on 2026-11-18, and the fits use LABSTAT's value. `src/ces_revisions/first_closing.py` holds the samples and fits, and `scripts/first_closing.py report` runs the check, then rewrites the generated tables of `specs/ces-revision-drivers-stage-9-findings.md`. No test guards that file's hand-written figures: after a rerun, check them by hand.
- `scripts/pilot_run.py` drives the pilot (`prior-predictive`, `fit`, `sbc`, `sbc-summary`, `compare-seasonal`, `choose-gpu`, `shares`, `shares-report`). `shares` summarizes a fitted run's posterior news shares into `docs/runs/stage-6/news-shares.json` and refuses a run fit to other data than the current panel. `shares-report` rewrites the Stage 2 findings table from that JSON alone. On a GPU host `pilot_run.py sbc` refuses more than one worker. On a 4-GPU instance, start one shard per GPU, each under its own `CUDA_VISIBLE_DEVICES` with `--workers 1` and its own `--start` and `--stop`, all into one `--out-dir`, and run `sbc-summary` once every shard has finished. `sbc-summary` exits 1 and names any replicate index below `--replicates` (default 100) that has no file, because a failed replicate leaves none and the verdict would cover only the rest. A replicate's seeds depend only on `--seed` and its index, so the split does not change the results (D7). `scripts/gpu_probe_grid.py` times the engine at the Stage 7–9 dimensions on one host and writes one record; on a rented GPU pass `--hourly-price`, and `--four-gpu-price` where Lambda rents a 4-GPU instance of the same type. `tests/test_seasonal_state_decision.py` checks `docs/decisions/seasonal-state.md` against `docs/runs/stage-6/seasonal-comparison.json` and the Mac grid record that it names, and fails if they change. `tests/test_pilot_news_shares.py` likewise checks that the Stage 2 findings table is `shares-report`'s rendering of `docs/runs/stage-6/news-shares.json`. It does not check the findings' hand-written figures, so after a refit, check them by hand. The rest of `docs/runs/stage-6/` is Stage 6's committed exit evidence, which no test guards. Write new measurements to `data/runs/`; re-measuring the committed ones means rewriting that record.
- `scripts/` holds research tools outside the package; `pythonpath = ["scripts"]` in `[tool.pytest.ini_options]` lets tests import them by bare name. `scripts/archive_inventory.py captures` (network) records every Employment Situation release and every BLS and Internet Archive copy of the seasonal-adjustment files in `docs/inventory/`, merges into the committed rows so that none is dropped, and stores every ZIP it opens in `data/seasonal/raw/`. `scripts/archive_inventory.py current` (network, light) fetches only the release index and BLS's two ZIPs, stores them, and appends one `bls_fetched` row for each, with no request to the Internet Archive. `scripts/archive_inventory.py adopt ZIP...` (offline, under `python -I`) stores a local ZIP only when a committed row records its digest and no ZIP is stored for that digest yet. `scripts/archive_inventory.py inventory` (offline) derives the archive inventory from that evidence and regenerates its tables, and the counts that the review's prose quotes, in `docs/ces-revisions-review.md`. Never hand-edit those CSVs, the generated blocks, or the text inside a `<!-- BEGIN FIGURE … -->` marker.
- `data/raw/` holds roadmap Stage 3's source files, committed with `manifest.csv` (each file's origin, SHA-256, size, and BLS's `Last-Modified` date): BLS's vintage files and revision table, BLS's historical release dates, the Employment Situation release list, the entries of the vintage workbooks' Comments sheet, the Philadelphia Fed's EMPLOY vintages and release dates, and `manual/es-reschedules.csv`, the one hand-keyed file, whose rows cite their sources. `scripts/vintage_sources.py fetch` (network) validates every payload and completes the full refresh in a temporary tree before promoting any source or cached workbook. Stage 9 adds the collection-rate sources: `bls/ce-collection-rates.tsv` (the header and the C1, C2, C3 and `CEU05000000RR` lines of LABSTAT's `ce.data.0.AllCESSeries`), `bls/ce.footnote`, and the Internet Archive copies of BLS's registry-receipts page in `internet-archive/cesregrec/`. `scripts/collection_rate_sources.py` stages them in the gitignored `data/cache/collection-rates/` with its two network commands (`fetch-labstat`, `fetch-archive`), and its `promote` is the only offline command that adds files to `data/raw/`. `vintage_sources.py fetch` keeps their manifest rows. `scripts/vintage_sources.py manifest` is the only offline rehash path after editing `manual/es-reschedules.csv`; never hand-edit any other file in `data/raw/`. `scripts/vintage_sources.py build` (offline) writes the artifacts of `ces_revisions.vintages` (the raw-value table, transformations, release-date index, long panel, stage labels, reconciliation, accounting decomposition, the collection-window day count `D_t` and the window to first closing `W_t` of each release, and the collection rates C1, C2 and C3 from LABSTAT and from each archived registry page) to the gitignored `data/panel/`; tests build the same artifacts from `data/raw/` once per session through `tests/vintage_data.py`. BLS refreshes the vintage files about once a year, weeks after its February benchmark release, and the network canary in `tests/test_vintage_sources.py` fails when it has.
- `src/ces_revisions/annual/` implements roadmap Stage 4. Its raw sources and manual table transcriptions are committed under `data/annual/raw/`; rebuilt parquet lives under the gitignored `data/annual/panel/`. Every derived value carries raw-cell provenance, a named transformation, and `observable_at`.
- `scripts/annual_sources.py fetch` loads `BLS_CONTACT_EMAIL` from the gitignored `.project.env` via `python-dotenv` and sends it in the `User-Agent` of requests to bls.gov hosts only, through `archive_inventory.open_url`, which every fetcher in `scripts/` opens its URLs with. `open_url` recomputes the header for each redirect hop (`archive_inventory.ContactRedirectHandler`), so a bls.gov response that redirects to another host does not pass the address on. Every other host gets `ces-revisions/0.1.0`. Never print or commit the address. The `manifest` and `build` commands are offline.
- `data/seasonal/raw/` is the committed store of the seasonal-adjustment ZIPs that `scripts/archive_inventory.py` opens: `ces.spec.ae/<digest>.zip` and `ces.spec.other/<digest>.zip`, each named by its base-32 SHA-1, beside `manifest.csv` (each file's SHA-256, size, and digest). Only `captures`, `current`, and `adopt` write it. Never hand-edit it. Git treats every file there as `-text` and the ZIPs as `-diff`. A `bls_fetched` row in `docs/inventory/archive-captures.csv` is a copy fetched from BLS's live URL, and its stored ZIP, not that URL, is its evidence once BLS replaces the file. A `payload_lost` row has no stored ZIP and credits nothing, and `adopt` stores its ZIP if the bytes turn up. Each network command needs the owner's explicit yes, every time. Run `current` after each monthly Employment Situation release, then `inventory`. `inventory` writes the review's release count, its counts of releases that keep each file type, and its latest reference month as generated text inside `<!-- BEGIN FIGURE … -->` markers (`render_figures`), so the summary bullets and inventory rows never carry a hand-typed or dated count. Prose that quotes a new count wraps it in a marker. After `inventory`, if the archive-complete count rose, set `ARCHIVE_COMPLETE` in `tests/test_archive_inventory.py` to the new count. If it fell, stop and report to the owner.
- Stage 4 stores CES benchmark and birth–death values in thousands and the raw QCEW revision sequence in jobs. QCEW timestamps distinguish the news-release quarter-end value from values that first appear in the full-data update. Sample coverage/RSE is annual, the coverage share is explicitly an active-report proxy, and the RSE definitions are not harmonized across their documented break.


pytest and ruff are dev dependencies. Ruff lints with its default rule set — already broad in ruff 0.16 (pyflakes, pylint, simplify, and partial bugbear/pyupgrade, among others) — extended with every `I` (import sorting), `B` (bugbear), and `UP` (pyupgrade, targeting Python 3.14 via `requires-python`) rule through `extend-select` in `[tool.ruff.lint]`. Don't switch that to `select`, which replaces the defaults rather than adding to them; tests live in `tests/`, and `[tool.pytest.ini_options]` registers the `network` (live BLS fetches, layout canaries) and `slow` (MCMC, end-to-end runs) markers and turns an unregistered marker into a collection error, so a misspelled marker can't slip past `-m` deselection. `ruff format` also scans Markdown (including `specs/`, `README.md`, and this file) and reformats Python code blocks inside it.
