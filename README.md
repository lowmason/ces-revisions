# ces-revisions

How large are revisions to U.S. nonfarm payroll employment from the BLS Current Employment Statistics (CES) survey, how has their size changed over time, and what drives it?

This project studies the **scale** of CES revisions — not only their sign or mean bias — and develops a Bayesian state-space model in which candidate drivers shift the *variance* of revisions. Calibrated estimates of revision scale are directly usable as measurement-error variances in real-time payroll nowcasts.

## Research scope

Each revision stage is analyzed separately:

1. First print → second print (one-month revision)
2. Second → third print (two-month revision; final sample-based estimate)
3. Third print → annual benchmark (preliminary and final March benchmark)
4. Post-benchmark revisions and wedge-back across intervening months

Candidate drivers of revision magnitude:

- **Seasonality** — the 2003 move to concurrent seasonal adjustment, X-13ARIMA-SEATS, calendar effects, COVID-era factor instability
- **Collection interval** — days between the reference pay period and first closing; collection and response rates
- **BLS funding** — real appropriations, continuing resolutions, sequestration, shutdowns
- **Sample** — design history, size, allocation, and collection mode
- **Staffing** — BLS employment and FTE counts

The design requirements call for a latent "true" employment path with vintage-specific measurement equations (the Jacobs–van Norden news/noise tradition), the QCEW benchmark as an irregularly timed higher-precision observation with wedge-back, joint NSA/SA modeling to separate seasonal-factor revisions from sample revisions, and partial pooling of driver effects across NAICS supersectors.

## Getting started

Requires [uv](https://docs.astral.sh/uv/) and Python 3.14.

```bash
uv sync                                      # create .venv and install the package
uv run ces-revisions                         # run the entry point
uv run python scripts/vintage_sources.py fetch     # network: staged, validated refresh
uv run python scripts/vintage_sources.py manifest  # offline: rehash existing sources
uv run python scripts/vintage_sources.py build     # offline: build data/panel/
```

The Stage 3 fetch validates every payload and completes PDF/workbook-derived
artifacts in a temporary tree before replacing anything in `data/raw/`.
`manual/es-reschedules.csv` is the only hand-editable raw source; run the
offline `manifest` command after changing it.

### Annual benchmark-source tables

Roadmap Stage 4 archives BLS benchmark articles, technical-note snapshots,
birth–death pages, and the national QCEW revisions CSV under
`data/annual/raw/`. The committed `manifest.csv` pins every source and manual
table transcription by SHA-256. Built parquet is reproducible and remains
gitignored under `data/annual/panel/`.

Set `BLS_CONTACT_EMAIL` in the gitignored `.project.env`; every network
request identifies that address in its `User-Agent` without recording it in
logs or manifests. Then run:

```bash
uv run python scripts/annual_sources.py fetch     # network + PDF text extraction
uv run python scripts/annual_sources.py manifest  # offline rehash
uv run python scripts/annual_sources.py build     # offline parquet build
```

The build writes dated benchmark, reconstruction, birth–death, QCEW-revision,
QCEW-precision, and annual sample/RSE tables. CES quantities are in thousands;
the long QCEW sequence remains in jobs. Its observation clock distinguishes the
early quarter-end value in a QCEW news release from prior-quarter revisions and
other current-quarter months that first appear with the full-data update.

### Deterministic operators

Roadmap Stage 5 turns the Stage 3 vintage panel and Stage 4 annual tables into
sparse float64 JAX operators and audited Polars fixtures. Rebuild the gitignored
artifacts with:

```bash
uv run python scripts/operator_artifacts.py build
```

The build writes the 2003–2025 benchmark-wedge fixtures, inferred post-March
components, the link-relative recoverability table, release-specific B→M
components, and `operator-test-results.json` under `data/operators/`. The
[link-relative decision](docs/decisions/link-relatives.md) records why every
public year uses an inferred cumulative job-change representation. Later model
runs copy the JSON record into their provenance.

The modeling stack is JAX, NumPyro, ArviZ, and Polars on Python 3.14, with fastexcel to read the source workbooks. The state-space engine is hand-written rather than taken from Dynamax, for the reasons recorded in [`docs/decisions/engine.md`](docs/decisions/engine.md).
